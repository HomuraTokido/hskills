# ring

在屏幕上弹一个来电窗口并响铃，告诉「マスター」一件事做完了。它是通知开关，不是通话。

## 什么时候打

- 「マスター」交代的一个任务真正做完，在最后一条回复之前打一次。
- 卡住了，需要「マスター」拍板才能继续，打一次，话里说清卡在哪，然后停在原地等，不催。
- 只回了一段话、答了一个问题、做完一个中间步骤，都不打。

## 怎么打

脚本在本 skill 目录下，权威源是 HSkills 的 `skills/ring/ring.py`。

```bash
python <本 skill 目录>/ring.py --from "Claude" "<一句话说完成了什么>"
```

宿主应使用已授权的 Python 解释器和本 skill 的 `ring.py`，按精确脚本路径配置执行信任。

Codex 调用 `exec_command` 时用 `sandbox_permissions=require_escalated`，让窗口出现在用户正在看的桌面。
沙箱中的脚本会在响铃前报错退出；不能把这个错误当成已通知，也不要在沙箱里重试拨号。

- 一句话不超过 30 个字，念出来要像人在电话里说话。
- `--from` 填当前宿主的名字。`--timeout` 改响铃秒数，默认 30。`--sound` 换铃声，Windows 自带的在 `C:\Windows\Media\Ring01.wav` 到 `Ring10.wav`。`--speak` 会同时用系统语音念一遍，默认不念。

## 怎么读结果

程序结束时打印一句话，就是全部的返回值，没有退出码要查：

- `「マスター」已经知道了。`：仅点击“我知道了”按钮时返回。
- `响了 30 秒，未点击确认按钮，不要再打。`：定时器超时。
- `来电窗口已关闭，未点击确认按钮。`：关闭窗口或其他未确认关闭。

若脚本报“来电窗口不可见”，这次没有响铃或通知；改用上面的真实用户层调用。

三种都是完整的结果；不要把超时或关闭推断成用户已看到或已确认。读到哪句都不重复打，不换别的方式再提醒，继续正常回复。铃响本身就是消息，Agent 记下就够了。铃声只响一次才值钱，反复打会让它从"有事完成了"变成"有东西在烦我"。

## 更新本机 Codex 副本

修改权威源码并验证后，用本目录的 `install_codex.py` 做窄同步：默认只列计划，
传 `--apply` 才更新 `~/.codex/skills/ring` 的脚本和 Skill 正文。旧文件备份到
`~/.ring/backups`，不触及其他 Skill、宿主配置或插件。安装也在真实用户层运行。

## 本机事实

- Codex 可在 `~/.codex/rules/default.rules` 中按本机解释器与 `ring.py` 的精确 prefix 配置执行信任。
- bundled Python 没有 tkinter；窗口使用 Windows 自带 WinForms，铃声和语音也只用系统能力，
  不安装第三方依赖。
- 记录追加在 `~/.ring/calls.log`，沙箱里写不了就跳过，不影响打印的结果。
