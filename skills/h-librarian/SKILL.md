# h-librarian

librarian 岗位的 skill。职责、范围和汇报格式以岗位合同为准，这里只记这个岗位干活时踩过、付出过代价的坑。

## 坑

### 新说法写回旧笔记：默认是「取代」，不是「更正」

笔记里的旧说法是当时查证的记录。新一次查证和它对不上，通常只能说明来源现在的说法变了，说明不了旧记录当时就错了：官方页面会改，改没改过往往查不到。所以写成「被 YYYY-MM-DD 的新说法取代」，旧句留着当历史，不写「更正：与官方不符」。

只有拿到旧记录当时就错的证据（当时读错了、引错了、来源当时就不是这么写的）才写「更正」。派活说明里写的「已经对不上，改正为……」只说明现在和旧记录不一致，不算这种证据，照样按「取代」写。

### 按 checked_at 列过期：别拼日期区间正则，拼了就对账

用几条区间正则拼出「截止日之前」很容易留缺口。例：截止日 2026-09-16 时，`checked_at: 2026-0[1-8]-` 加 `checked_at: 2026-09-1[0-5]` 漏掉了 09-01 到 09-09 和 2026 年以前的所有日期（未验）；其中一条没结果，也只说明那一段没有，不说明过期的都找到了。

做法二选一：

- 把所有 `checked_at` 的值列出来，逐个和截止日比。
- 一定要拼区间时，把截止日之前的每一天都盖住（当月 1–9 日、往月、往年），再对账：过期笔记数 + 未过期笔记数 = 带 `checked_at` 的笔记总数。对不上就是区间或日期写法漏了，查清再交清单（未验）。

grep 的结果有条数上限，整库搜 `checked_at` 会被截断（见过 200 条、400 条就截，未验）。截断的结果列不全，也对不上账，原样重跑同一个搜索还是截断。按目录分开搜，让每一段都不截断，再合起来比对、对账。

### read 连报 ENOENT：先查路径基准

同一批文件连读几次都报 ENOENT，通常不是文件不在，是路径基准错了：工作目录本身已经在仓库的某个子目录下，再按仓库根拼一层就多出一层。这时继续换别的文件名重试，换几次也还是同一个错。停下来核一次工具实际用的基准，改成相对工作目录的路径，一次就能读完（未验）。

### edit 报找不到原文：重读那一段，逐字复制锚点

edit 的旧文本要和文件逐字一致。凭印象复述的锚点差一点就报 `Could not find the exact text`：多一对括号、给正文段落添上列表的前导「- 」，都会这样（未验）。把锚点截短也救不回来，差的字往往就在留下的那段里。例：原文是「…不如做法 A 一份文件两行。」，记成「…不如做法 A（一份文件两行）。」，整句和截成「（一份文件两行）。」各报一次找不到（未验）。报找不到就别再猜着改锚点，先重读那一段，从读到的输出里整行复制再提交。

### 回链找不到「相关」节：新建，别跳过

在要回链的笔记里 grep `^## 相关` 没结果，只说明它没有这个标题，不说明这条回链可以不加。先看一眼尾部，确认没有别的写法的同类段落；真没有就在末尾新建「## 相关」再加。跳过了就只剩单向链接，互链没做完。
