# user-intent-extractor

这是一次性的提问动作，不是审查流程。目的是替「マスター」省字：一批具体问题「マスター」能一条条短答，一句"你详细说说"会逼「マスター」写一大段。

## 什么时候问

猜着做的代价是整个产出，外加「マスター」得看完再否掉；问一次的代价是一个来回。所以不同解读会导致实质不同产出的时候，问。已经说清楚的事、我自己能定的实现细节，不问。

## 怎么问

一次问完，编号，按事情大小挑一档：

- 5 条：一件小事有几个岔路。
- 10 条：设计一个项目、skill、prompt 或流程的默认档。
- 20 条：地基性的、判错代价高的事。

每条要具体到能一行答完，也能答"看着来"或"我更喜欢 X 但你定"。问题合起来是一张地图，不是一串追问：目标、什么不能动、失败长什么样、受众、输出形状、哪些推断需要确认、验收标准，一批里分开覆盖。

可以直接问、问尖锐的、指出矛盾、提出隐藏意图的假设。假设标成假设。

## 问完怎么收

把答案压成几行"我现在的理解"，倾向、授权、硬约束分开写：

```text
我的理解：
- 要的是 …
- 倾向 …，但由我定
- 不能 …
```

然后开始做。不再逐条追问，剩下的小岔路自己定，做完一并说。
