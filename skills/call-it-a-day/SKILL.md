# call-it-a-day

收工。「マスター」要离开电脑一段时间（收工、睡觉、出门），把这次会话收完再报给ta：这次会话做的 commit 先 push 上去，再把剩下的尾巴一次点清，哪些要ta拍板，哪些我已经收好，哪些还开着。

## 什么时候用

- ta说收工、要睡、要出门、「今天就到这」「先这样明天再说」。不必是字面：意思是这一轮结束、ta接下来一段时间不在电脑前。
- 话里还带着一件要做的事（「我要睡了，先把这个改完」），先把那件做完，再收工。
- 暂离不算：吃饭、「等我一下」「一会儿回来」。这时只提一句正在跑、可能需要ta的东西，不做清点。

## 为什么收工就 push

ta干活时不想被 push 状态打断：没 push、已 push、要不要 push，平时一律不说。例外是中途要看 CI，那时 push 本身就是那一步。

收工不一样：没 push 不算收完。ta叫这个 skill，就是要这次会话的 commit push 上去，不是让ta再答一遍「push 吗」。所以调用这个 skill 本身就是ta对这些 commit 的会话级 push 授权（文字回复里不再重复问一遍；若宿主启用了 `rules/hooks/confirm-push.mjs` 且该仓库未设 `git config --local claude.allowPush true`，直接执行 `git push` 并由 hook 弹窗完成最终放行确认，已设 `claude.allowPush=true` 的常驻仓库则直通）。

范围只到这次会话里我做的 commit，在这次会话碰过的仓库里。会话开始前就有的、别的会话或别的宿主留的 commit，不在这个授权里，列出来问。

## 收什么

只看这次会话碰过的东西：对话里出现过的仓库、服务、文件、设置。不扫全盘。

1. **git**：每个碰过的仓库先 `git fetch`，再跑 `git status --short --branch`。
   - 没提交的改动：属于这次授权的活、项目允许本地 commit 的，直接 commit；说不清是谁的（会话开始前就在的、别的会话留的），列出来不碰。
   - 没 push 的 commit：这次会话做的，直接 push（见下一节）；不是的，写仓库名和条数，问 push 不 push。
2. **还在跑的**：后台命令、派出去还没回来的单、dev server、定时任务、loop。说清它们在ta不在时会不会继续花钱或改东西，问停还是留。
3. **临时改动要复原的**：这次为了测试切过的开关、改过的配置、关掉的程序。能复原的先复原，清单里说一句；复原不了的说清现状。
4. **没收尾的承诺**：说过「之后再做」「等你定」的事，没验证完的结论，ta说过「你记得就行」的事。记进 ai-todo 看板（`ai-todo`，用法见那个仓库的 README）：ta批过的建正式条目，写下ta的原话；「等你定」的建草稿。清单里说记了几条。这次会话里ta的纠正和决定还没记下的，追加进这个宿主自己的 daybook（Claude Code 是 `~/.claude/daybook.md`；一条一行，只写陈述句，不提交、不同步），不判断它是不是规则。本机没有 ai-todo 时，没收尾的事也先记进 daybook，并在清单里说一句。
5. **ta回来前会到期的事**：额度重置、过期、续费、截止日。只查项目里本来就有的日程记录，不另去找。

没有尾巴的项不写。

## 怎么 push

- 本地落后于远端或已经分叉，停下说，不自己 merge 或 rebase。
- pre-push 检查没过，不跳过检查，报哪一步没过。
- 有 CI 的，push 完等结果。ta已经走了，就把结果留在会话里：绿还是红，红的话红在哪一步、是不是这次的改动引起的。

## 怎么报

ta要走了，可能在手机上看。

- 第一句给结论：全部收完、能直接走，还是有几件要ta定。还有没 push 上去的（被拦下、落后、不是这次会话做的），不说能直接走。
- 要ta定的放最前，每件一行，能用「好」或一个词回答，例如「specialist-subagents 有 3 个 commit 不是这次会话做的，push 吗」。
- 我已经收好的，每件一行；push 了的写仓库名和条数。
- 不复述这次做了什么。那是总结，不是清点。
